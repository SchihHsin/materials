# 用户旅程图参考

## 字段口径

| 行 | 回答的问题 | 写法 |
|---|---|---|
| 阶段 | 用户正处在哪段过程，想达成什么 | 动词短语，如“配置环境”“验证结果” |
| 触点 | 用户实际接触什么 | 页面、工具、文档、服务人员、通知等具体对象 |
| 行为 | 用户做了什么 | 一条主动作链，必要时配截图或 mini UI |
| 情绪 | 用户主观感受如何变化 | 高低相对值 + 触发原因，不能凭空写戏剧化情绪 |
| 痛点 | 哪个环节阻碍目标 | 事实 + 后果，避免“体验不好”这类空话 |
| 机会点 | 如何针对该痛点改善 | 具体机制或能力，不写“优化体验” |

## 信息压缩

- 一个阶段只保留一个用户目标、1--3 个触点和 1 条行为链；痛点格和机会点格通常各列 **至少 3 条**，每条机会点回应同列的一条痛点。证据不足时可少写，但不能为了视觉齐整硬塞内容。
- 原始证据很多时，优先把原话或量化数据放进痛点句中，例如“版本矩阵分散，需反复比对，首次安装平均耗时 3 小时”。
- 用户目标和机会点要有可验证关系：用户想“确认环境可运行”，机会点应是“提供依赖检测与一键修复”，不是泛泛“增强引导”。
- 情绪只画相对变化。首尾曲线相接只是视觉连续，不暗示不存在的精确测量。

## 改列规则

模板默认 5 列。改为 N 列时，替换所有 `.jrn-grid` 的 `--jrn-cols:N`，不要逐行手改 `grid-template-columns`。

- 3--4 列：可以保留每格 mini UI，正文可稍长。
- 5--6 列：每格文案应更短，mini UI 高度保持一致。
- 7 列及以上：优先拆图；用户明确要求高密度时可保留，但删掉次要触点和重复描述，不能缩小正文。

## 常见错误

- **按事项而非用户阶段分列**：把“文档、工具、服务”当成列，导致无法读出用户过程。改为阶段列，把事项放进触点行。
- **痛点与机会点脱节**：机会点放到别的列，观众看不出解决谁。改为同列对应，或用小序号连接。
- **跨列一条情绪线**：列宽变化后会错位。每格单独绘制，首尾 y 值相接。
- **行高由内容撑开**：一列文字多就把全行拉高。正文限量，情绪行与 mini UI 用显式高度。
- **到处都是颜色**：阶段色只作为阶段头的底部细条；痛点、机会点使用语义色；其他内容保持中性。
