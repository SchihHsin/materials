# Report PPT Skill（汇报材料网页 PPT）

> 来源：本 skill 由 CANN DesignConcept 2026 汇报 deck 提炼，面向"分析 + 方案"型汇报材料。区别于 `guizang-ppt-skill`（杂志风 / 瑞士风、偏分享演讲）——本 skill 偏**企业内部产品/设计/研究汇报**，信息密度更高、有成体系的组件（胶囊指标、甘特、用户画像、竞品对照、旅程图）。

## 这个 Skill 做什么

生成**单文件 HTML** 的纵向整页翻页 deck（也可多分册各自成文件，最后用 `build_index.py` 模式合并成一个 `index.html`）。核心 = **三基调 + 一套设计 token（字号 ramp / 渐变色彩 / 玻璃卡 / 鸿蒙字体）+ 一组可复用组件**。

- 翻页：**原生纵向 scroll-snap**（`body` 作滚动容器，`.slide` 满屏 `100vw/100vh` + `scroll-snap-align:start;scroll-snap-stop:always`，划时短暂两页、松手吸附到整页）；当前页用 `IntersectionObserver` 判定。键盘 `↑↓←→`/空格/PageUp-Down/Home/End，右侧竖排 `.nav-dots`。
- **整套 deck runtime（不可拆）**：以 `assets/deck-template.html` 为起点，保留其纵向翻页、底部图标控制栏、右侧导航点、概览、全屏、键盘操作与 URL 页码定位。控制栏默认隐藏，鼠标进入底部区域才出现；概览为按当前视窗比例缩放的缩略图网格，全屏走 Fullscreen API。**不得另写简化文字控制条，也不得只补其中一个功能。**详见 `references/deck-architecture.md`。
- 自包含：纯 HTML/CSS/SVG，外链仅字体 CDN + 可选图表库；可离线（库 inline 到 `lib/`）。
- 不能生成 AI 图：背景大图需用户提供，或 `curl` 下载网图（Wikimedia / YouTube 缩略图 `img.youtube.com/vi/<id>/maxresdefault.jpg`）。

## 三基调（先选基调，再填内容）

| 基调 | 底色 / 氛围 | 承载内容 | 关键视觉 |
|---|---|---|---|
| **① 封面** | 大图作底 + 深色侧向叠加 | 标题页 / 章节封 | kicker（等宽小字）+ 超大 logo/标题 + 副标 + lead；品牌左上、出品方左下 |
| **② 灰底分析篇** | 冷灰 `#E9EBEE` + 底部大波浪 | 数据 / VOC / 竞品 / 旅程 / 画像 / 甘特 | **玻璃折射白卡** + 蓝紫 accent + 渐变色块 |
| **③ 黑底设计点** | 纯黑 `#06060a` + 底部渐变光晕 | 问题 / 方案 / 设计点 | **渐变标题字** + 一章一色（可调色面板）+ 玻璃拟态图位 |

> 一份完整汇报常按 **封面 → 灰底分析（现状/洞察）→ 黑底设计点（方案）→ 灰底 roadmap（甘特）** 串。

## 工作流

1. **澄清（动手前必做）**：主题 / 受众 / 章节大纲 / 有无现成素材（背景图、截图、数据）/ 每页大致放什么内容。结构定错后期翻修代价高。
2. **先定叙事与文案（新增，先于视觉）**：写出受众要做的决策、整份汇报的核心判断、每章回答的问题和相邻章节的承接；再按任务选择体验优化 / 评测竞品 / 设计提案 / 领导决策摘要等叙事模式。将证据、基于证据的推论与待验证的方案分开，并为重要发现写明对应的设计响应、用户收益和指标或依赖。详见 `references/narrative-and-copy.md`。**这一步只组织内容，不改变本 skill 的封面、三基调、组件和 runtime 规范。**
3. **选基调 + 起模板**：复制 `assets/deck-template.html` 为起点。**先保留完整 deck runtime，再删改示例页、填内容**；runtime 包括 CSS/HTML/JS 中的控制栏、右侧导航、概览、全屏、键盘、翻页与 URL 定位，不能用新写的一小段控制条替代。
4. **逐页选件（关键，别跳）**：对每页内容先按下表路由，命中就去 `components.md` 对应节**照抄骨架 + 填充示例**，只改文案/配色；没命中才考虑自定义，**绝不一上来手搓**。

   | 用户说的（触发词，中英文均算） | 命中件 |
   |---|---|
   | 几个大数字/百分比/转化率/达成率/KPI overview/metrics/数据概览 | **§1 渐变胶囊指标** |
   | 计划/排期/里程碑/时间线/roadmap/甘特/泳道/Q1Q2/什么时候上线/sprint | **§2 甘特 roadmap** |
   | 用户反馈/原声/吐槽/访谈摘录/语录/VOC/voice of customer/调研摘要/客户怎么说 | **§3 VOC 声音墙** |
   | 全流程/各阶段/端到端/触点/情绪曲线/journey/全链路/操作步骤的痛点/用户怎么一步步做 | **`user-journey-skill`**（独立旅程图 skill；每条情绪线按格绘制，且各自相邻格交界 y 值必须严格相等） |
   | 竞品/友商/对手/同类工具/横向对比/benchmark/A vs B/选型/市面方案 | **§5 竞品对照** |
   | 介绍某个用户/他是谁/他的日常/角色特征/职责场景痛点/persona（单人·正式深描） | **§6a 用户画像·形式一**（左栏+右侧多区） |
   | 几类用户有什么不同/角色对比/能力维度对比/雷达图/多角色对照 | **§6b 用户画像·形式二**（顶栏+雷达，ECharts） |
   | 工作坊/共创/白板式/便利贴风画像/性格+动机+目标+痛点+问题+解法都要（单人·看板速写） | **§6c 用户画像·形式三**（左紫栏档案+右便利贴墙） |
   | 卡片底部补几个小数字/附加指标/标签+数值 | **§7 KPI 小数字组** |
   | 三个并列要点/三个同级原因或目标/三项原则/四个以上同级模块/一组同层级信息卡 | **§17 同层级信息卡**（按卡片数量选样式） |
   | 设计理念/方案亮点/我们的解法/核心设计点/问题→方案/design concept | **§8 黑底设计点** |
   | 干系人/利益相关者/生态/stakeholder map/ecosystem/以某角色为中心的关系图 | **§12 生态干系人地图**（同心圈层 SVG + 卫星 + 关系箭头）|
   | 优先级/机会矩阵/价值×成本/影响×成本/2×2/四象限/impact-effort/quick wins | **§13 2×2 机会矩阵**（bento 四块 + 便利贴 + 燕尾箭头轴）|

   | 需要围绕一组证据逐条讲解；没有现成承载物时新绘证据矩阵，有现成矩阵/旅程图/流程图/截图组/架构图时叠加聚光灯讲解 | **§15 证据聚光灯**（`evidence-spotlight-matrix`）|

   | 目录/章节目录/contents/agenda/这一份汇报讲什么/章节概览 | **§18 目录页**（`contents-directory`）|
5. **套规范**：字号只用 ramp（`references/type-and-color.md`）；小面积语义元素用纯色 `--c-*`，大面积强调面用同色相渐变 `--g-*`，深色大色块统一 `--g-ink`。
6. **图表**：能手画就手画（胶囊/甘特是精调模板）；复杂图（雷达/桑基/热力/关系树）才上 ECharts/ApexCharts（`references/chart-selection.md`）。
7. **多分册合并**（可选）：每个基调一个源文件，跑 `build_index.py` 合成单 `index.html`（机制见 `references/deck-architecture.md`）。
8. **交付前逐页跑质检**：对每一页过一遍 `references/checklist.md`（叙事 / 文案 / 字号 / 溢出 / flex `min-height:0` 卫生 / 对齐 / 图片 / 视口陷阱），按表里的"正确做法"改，别靠肉眼微调凑——**这是生成效果好坏的关键一步**。
9. **交付**：浏览器 `open` 自检；每次改完 **git push**（用户偏好）。

## 铁律（最容易翻车的几条）

- **先路由再动手**：每页内容**必过 `components.md` 顶部「选件路由表」**对号入座，命中精调件就照抄、别另造（复用 skill 时命中率最低、最容易丢掉精调件的一步）。
- **🔴 deck runtime 是整件复用，不是可选装饰**：新 deck **必须从 `assets/deck-template.html` 复制并保留** `#controls`、`#navDots`、配套 CSS 和整段 runtime JS；不得手写常显的大号文字胶囊，或先省略概览/全屏、等用户要求后再拼。控制栏必须是小型图标按钮，底部 hover 显示；总览必须是按当前窗口比例缩放的可点击三列缩略图网格；全屏、键盘、页码 URL 与翻页状态同步。多分册合并时只保留一份完整 runtime（见 `deck-architecture.md`）。
- **标题 = 结论导向**：每页标题直接说出该页的「主要发现 / 结论」，不要写空泛词（❌「用户研究」→ ✅「文档、调试、环境是三大核心障碍」）。英文+说明放副标题。
- **叙事与文案先成立，再上版式**：每章只承担一个主要问题；页面标题写发现或设计判断，不当导航词。正文明确证据、推论、方案的边界；方案页优先写成「设计图 / 示意 → 3--4 个体验点 → 用户收益、验证方式或依赖」。重要发现必须有响应、边界或明确不处理的决定；每个设计点都能回指发现、目标或原则。详见 `references/narrative-and-copy.md`。
- **目录页按章节数固定排版**：目录 / agenda 使用 `components.md §18` 的 `contents-directory`；每卡是「大章节号 → 章节名 → 英文辅助名 → 1--2 个内容锚点 → 一句章节职责」。**3 / 4 / 5 章一律单行横排，6 章才用 3×2 上下两行**；7 章及以上先合并章节，或拆为主目录 + 附录目录，不能缩小卡片硬塞。目录只建立阅读路径，不提前写发现或方案结论；章节名必须与后续页 `.subttl`、页脚和总结一致。
- **字号只用 6 档 ramp**（h1/h2/h3/body/sm/xs），别手写 `max(13px,.9vw)` 这种。超大展示数字（封面大字、大百分比、章节序号）属 bespoke，不进 ramp。
- **⛔ 字太小是最常见翻车——三条硬规矩**：① **正文一律 `var(--fs-body)`（≈14px@1440，舒适可读）**；`--fs-sm`/`--fs-xs` **只**给"次要说明 / 标签 / 注释 / 页码"，**绝不拿 sm/xs 当正文**（"整页字都很小"十有八九是正文误用了 sm/xs，或手写了更小的值）。② **内容多 → 精简文案或拆成两页，绝不靠缩字硬塞进一页**。③ **密集小字（如用户画像 12–15px）是个别特殊件的局部例外**（在 `.pf/.pp/.up` 上局部冻小），**别把这种小字推广到普通页**。
- **颜色分两层用**：小面积语义元素（标签、Lucide 图标、线/点、卡片局部光带）用 `--c-*` 纯色；大面积强调面（突出卡、宽色带、光晕、面积填充）用同色相 `--g-*` 渐变。每页选 1 主色 + 至多 2 辅色，不能为了“色谱全”做彩虹墙；红/橙/黄只用于风险、提醒、进行中等语义，绿/薄荷用于机会和完成，`--g-ink` 统一用于深色大块。**相近色不要凑在同一张卡片墙**：靛/紫、红/玫红、绿/薄荷默认二选一，橙/琥珀/黄最多两种。
- **同层级信息卡按数量选样式**：仅用于无专属组件的并列同级内容（不是竞品、指标、画像、流程或时间轴）。**恰好 3 张**必须是白玻璃 / `--g-accent` / `--g-ink` 三层，依次承载事实、重点、结论，不能三张同色白卡；**超过 3 张**必须全部为透白玻璃卡，使用 `--c-*` 驱动同卡标签、Lucide 大图标和顶部横向淡光带，禁止实色满铺、顶部色描边和每张卡重复同一种颜色。4--5 张默认靛/蓝/青/绿/粉，紫只在策略/创新语义下替换一张。**无论三张、四张或更多**，阅读组固定为标签 / 两行标题 / 三行说明三轨，再整体居中；三张卡的标签、标题、说明必须跨卡对齐，说明变长只占自己的三行轨道。标题 `--fs-h1`、说明 `--fs-h3`，标签到标题用紧凑间距，不能做成贴顶标签 + 底部小字。完整骨架见 `components.md §17` 与模板库。
- **卡内标签必须随内容收缩，绝不当整行色条**：分类 tag / chip / badge 默认是文字的紧凑容器，而不是卡片分隔线；用 `display:inline-flex; align-self:flex-start; width:fit-content; max-width:100%`，保留左右内边距和 `border-radius:999px`。**禁止**在标签上写 `width:100%`、`display:block`，或把它放进会 `align-items:stretch` 的列布局却不覆写 `align-self`。标签过长时优先精简为 1--3 个词；确有必要才在自身最大宽度内换行，不能横向撑满整张卡。完整骨架与质检见 `components.md §17`、`checklist.md`。
- **列布局间距别用 flex 列**做瀑布墙（高度推挤 + `margin-top:auto` 会出诡异间距 bug）→ 用 `column-count`。
- **⛔ 所有 flex 列 / grid 子项默认带 `min-height:0`（横向再带 `min-width:0`）**：否则子元素不收缩、内容一多就撑破父容器溢出——"等高对不齐 / 某栏比另一栏高 / 卡片气泡越界 / 文字被裁"几乎都是漏了这条（复用 skill 时最隐蔽、最费手调的一类坑）。等高靠 grid `align-items:stretch`；想让某栏吸高度差**只给它一个 `flex:1`、其余 `flex:0 0 auto`**；整块别用 `flex:1` 填满超高屏（4K 注水）→ `flex:0 1 auto`。
- **绝对定位子元素无视父 padding** → 需要内边距时加一层 `position:absolute;inset:...` 的内层容器。
- **⛔ 页面标题前默认什么都不放——绝不加装饰性 icon**（复用 skill 时最常翻车的一条）：head 的 `.brand` 槽**默认留空，只有标题 `.ttl`**；**仅当用户明确要 logo 时才加**（`<img class="logo" src="CANNlogo.png">`，深底用 `cann-dark-logo.svg`；用户给了别的真 logo 就换那个）。封面 `.cv-logo` 的大 logo 不在此列（封面照常有）。**严禁**在标题/区块标题前顶 Lucide / 通用 SVG 图标。装饰 icon 仅限个别精调组件内部（如画像 `.pf-h2`），不是通用模式。
- **logo 用图片、且分深/浅两版按底色选**：深色底（封面 / 黑底页）用白/反白版，浅色底（灰底页 head）用深色/彩色版；**别把深色 logo 放深色底**（看不见），也别手敲文字拼 logo。详见 `components.md §0`。
- **⛔ 不用 emoji；需要图标时优先用 Lucide**：凡要图标的地方（状态、操作、图例、卡内点缀、KEY 说明、淡水印大图标等）**优先从 Lucide 开源图标库选**，用 `<i data-lucide="icon-name"></i>` + `lucide.createIcons()`，或直接复制 Lucide 的线性 SVG；只有 Lucide 没有合适语义、或需要业务专属概念图时才自绘 SVG。图标保持线性描边：`fill=none;stroke=currentColor;stroke-width≈1.6–2;stroke-linecap/linejoin=round`，跟随文字色。**严禁 emoji**（😐⏱✅❤◷ 等）——emoji 随系统/平台变样、自带彩色破坏冷灰+蓝紫统一调性、基线对不齐、显得不专业。**唯一例外：用户旅程「情绪曲线」可用 emoji 表情脸**（😐😕😤😩…，表达人的情绪起伏比线性脸更直观传神）——仅限**情绪曲线这一处的表情**。此约束不放松上一条「标题前默认不放 icon」——是说**当确需图标时优先 Lucide、不能用 emoji（情绪曲线表情除外）**。
- **用户旅程情绪线不可断**：旅程模板允许每阶段一格、格间留白，且应保持这种逐格布局；但是每条独立序列在相邻格公共边界必须同高。两产品/两人群对比时，各自沿自身序列计算共享边界值（如 `endY[s][i]=(y[s][i]+y[s][i+1])/2`、`startY[s][i+1]=endY[s][i]`），不同序列不要求同高。不能用“前中心 → 当前中心 → 后中心”各画一段。交付前在桌面视口按每条线逐个边界检查。
- **🔴 复用优先于重画**：要把另一份**已精调好的报告 / 图表页**搬进来时，**别照着手搓**（手搓版内容更少、更丑、丢交互，几乎必被打回）→ `iframe` 嵌原件 + 注入 `embedfix` 只露目标元素（带 no-flash 防闪、懒加载、wheel 转发）。判断顺序：原件有→嵌 / skill 有精调件→套 / 都没有才手搓。详见 `pitfalls.md`「嵌入复用」。
- **🔴 配图要「内容相关」，不是生搬 icon**：① 文字太多不好读的页 → 拆**左文字 + 右 demo/示意**（浏览器框、版本徽章、清单、渠道/公式图…），密度立降；② 概念页配图画**真·小 SVG 图**（对照=天平、价值链=漏斗、检索=放大镜→文档…），别放通用线性 icon（用户会说「只是个 icon、我以为有图」）。这与上面「标题前默认不放 icon」不冲突——那条管**标题装饰**，这条管**正文配图**。详见 `pitfalls.md`「配图」。
- **🔴 配色讲主次**：装饰性元素（类别标签、icon、出处）用**中性灰**，颜色只留给**有含义的功能元素**——满屏单一 accent ＝「AI 味重、没主次」。别用「左描边 accent 条」卡片（套路、AI 味重）→ 1px 整框柔阴影 / 白底+角落径向光晕。详见 `pitfalls.md`「配色 / 视觉主次」。
- **🔴 汇报文案：书面、简洁、易懂**：去口语化（「喂人喂 AI、下场、躺、兜底、慢但复利」之类全改）；专业 OK，但**不常见的词换常见的**（「结构性缺口」→「系统性短板」），术语配通用译法。
- 详见 `references/pitfalls.md`。
