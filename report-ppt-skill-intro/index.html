02 · Open-source HTML PPT

市面上已出现开源网页 PPT Skill，但仍存在设计研究材料的表达缺口

04 / 背景

我们的观察是：开源 Skill 已能生成风格化演示，却主要服务单一观点的讲述。

  • 01有标题、留白和翻页，缺少角色、场景与证据关系的专属结构。
  • 02旅程、画像、生态与机会矩阵，仍会退回通用图文排版。
  • 03信息密度上升后，结论、证据与设计响应难以形成决策链路。
03 · Extend into a system

通用 Skill 不足的部分，可以从既有能力继续扩展成自己的模板

05 / 背景

扩展的重点不是重做演示，而是把已有能力补成设计师可复用的材料系统。

  • 01补齐用户旅程、画像、竞品与机会矩阵等专属结构。
  • 02把内容路由、表达规则和视觉 token写成可执行规范。
  • 03用翻页、概览和 URL 页码，让材料可讲、可跳转、可复用。

guizang 等开源网页 PPT Skill通常以约 6 个通用页面组织内容，更适合单一观点的演讲式展示。

Template coverage

用户旅程、三种用户画像、干系人地图、竞品对照、机会矩阵与数据进展都有对应结构。

Information density

让证据、判断与设计响应同时可读

按材料任务组织信息层级，而不是在同一通用版式中靠缩字或堆卡片完成表达。

Language + runtime

规则不仅管样式，也管怎么讲

标题写结论、区分证据与方案，并保留翻页、概览、全屏与 URL 页码定位。

Advantage · Narrative and language

语言规范让汇报从“描述内容”转向“清楚表达判断”

10 / 优势
Title

标题写结论，不写导航词

标题脱离版式也应独立成立，直接说清受众要记住的发现或选择。

不写：用户研究 / 方案介绍
写成：文档、调试与环境构成三类核心障碍
Evidence

严格区分证据、推论与方案

证据是事实；推论标明判断；方案是待验证的设计响应，不能把承诺当结果。

用“表明 / 因此判断 / 建议 / 拟通过”明确边界
Design point

方案要说用户能理解、判断或控制什么

每个设计点对应问题、作用机制、用户收益，以及必要的依赖或验证信号。

不写：让体验更清晰、更高效
写成：前置关键状态，让用户知道现在发生什么、下一步能做什么
Tone

书面、简洁、命名一致

去掉口语、空泛词和不常见表达；内容多时拆页，不靠缩字或堆术语。

把复杂概念翻译成听众可判断、可行动的语言
