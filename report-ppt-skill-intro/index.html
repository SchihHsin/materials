优势一：20 个专属模板页，是通用开源 PPT Skill 的 3.3 倍

08 / 优势

模板页数量对比：同一套设计汇报任务，需要的不是更多同款版式，而是不同信息关系的专属表达。

3.3×倍
BEFORE · 约 6 页

通用模板只能承接基础图文

标题、图片与基础叙述可以完成；遇到旅程、角色关系或机会判断时，往往只能用同一种图文结构拼接，重点关系难以被看见。

AFTER · 20 页

按任务匹配专属模板

用户研究、设计分析、数据进展与设计点各有对应结构；把证据、判断和方案放进合适的表达骨架，无需为复杂内容反复造版。

Advantage · Information density routing

优势三：形式服务于内容，根据叙事内容及信息密度定义样式、布局与字号

09 / 优势
信息密度不是字多字少：灰底分析页按 D1–D4 与 A1–A3 选择表达骨架。第一步先判断读者主要在“读分析”，还是在“看方案”：文本、数据和字段按 D1–D4 增加结构；图、界面与关系图按 A1–A3 承载分析证据。

灰底分析篇

从大字结论开始；密度上升时增加结构，不靠不断缩小正文。

D1

低密度：1 主张 + 2–3 支撑
D2

标准分析

中低密度：1 判断 + 1 组证据
D3

中高密度：1 判断 + 3 信号 + 4 动作
D4

高密度：多维对照，必须结构化

灰底分析视觉页

Advantage · Page routing · Design

优势三：形式服务于内容，根据叙事内容及信息密度定义样式、布局与字号

10 / 优势
图像、界面与路径要承载设计叙事时，转入黑底 B 系列。判断问题：这张图是在作为分析证据，还是在带领设计叙事？前者使用灰底 A 系列；后者才使用黑底 B 系列。两者都有图，但阅读目的不同。

Advantage · Narrative and language

优势二：制定语言规范，把“怎么写”也纳入 Skill，保证材料的叙述质量

10 / 优势

此前，材料生成主要依赖作者或模型的临场判断，即使版式正确，文案仍容易出现标题空泛、证据与方案混写、设计点只讲感受等问题。

标题必须直接写出发现或设计判断，不用“用户研究”“问题分析”这类导航式标题。
论证先写可回溯的证据 → 基于证据的推论；方案单列，并补充用户收益或验证方式。
设计点写清用户能理解、判断或控制什么，避免只写“优化展示”“提升体验”。
表达统一书面语、命名和信息密度；内容过多时精简或拆页，不以缩小正文字号硬塞。

Advantage · Open-source libraries

优势六：合理复用开源库，让图标、图表和关系图兼具表达效率与呈现质量

13 / 优势

Practice · Version management

用 Git 留下每次判断的依据，让材料可以比较、回退与持续迭代

21 / 实践落地

Git 在这里不是额外的工程仪式，而是一套把材料变化变成可追溯记录的工作方法：左侧说明每个动作在写材料时的作用，右侧展示本 Repo 的真实迭代节点。

GIT ACTIONS · 动作定义写材料时如何使用
git pull获取最新版本

开始前先下载团队已更新的材料，避免基于旧版本继续修改。

git diff查看改了什么

提交前逐项确认文案、样式和图片的变化，排除误改或遗漏。

git commit记录本次更改

为这个版本写清“改了什么、为什么改”；之后可按记录比较、回退或复用。

git push上传给团队使用

将已确认的版本同步到远端，方便评审和后续协作从同一版本继续。
