# 用户旅程图 Skill

把散乱的访谈、行为记录与流程材料，压缩成一张能看清「用户在哪一步、做什么、感受如何、为什么卡住、该改什么」的旅程图。它不是普通流程图：每个结论必须落到对应阶段和证据。

## 开始前

1. 先提取阶段、用户目标、触点、行为、情绪、痛点、机会点；缺失的证据标为待验证，不要编造。
2. 先给出阶段和每阶段的一句话目标，请用户确认；已有材料清楚时可以直接制作。
3. 选择列数：优先 4--6 阶段；少于 3 阶段改用流程图；超过 6 阶段拆成两张连续旅程图，或只保留关键阶段。
4. 复制 `assets/user-journey-template.html` 作为起点。只改数据、阶段列数和 mini UI，不要新手搓一个卡片墙。

## 结构铁律

- 一列代表一个连续阶段，六行按固定顺序：阶段、触点、行为、情绪、痛点、机会点；不得把痛点集中到页面底部另列。
- 每阶段先写用户目标或任务，再填写触点和行为；每个阶段的痛点格和机会点格通常各列 **至少 3 条**，并逐条对应。证据不足时可以少写，但不要为了凑数编造问题。
- 触点写用户实际接触的界面、渠道或人，不写抽象能力名词。
- 行为最多一条主动作链；可以用真实截图，缺截图时用不同的手画 mini UI 表达该步骤，不能五格复制同一个浏览器框。
- 情绪是逐格相接的曲线，不跨整行画一条大折线。允许仅在这行使用表情脸；其他位置不用 emoji，需图标时优先 Lucide 线性图标。
- 痛点固定暖红语义，机会点固定绿色语义；同一阶段内的多条项目共用语义色，不另按类别染色。颜色不是分类装饰，不能互换。

## 版式与可读性

- 列数由 `.jrn-grid` 的 `repeat(N, minmax(0, 1fr))` 统一控制，六行全部同步；首列固定为行名。
- 阶段标题区统一最小高度；内容长短不同也要保证阶段头、正文起点和底边对齐。
- `.jrn-grid.je` 的高度必须显式锁定；情绪元素都是绝对定位，删掉高度会被压扁。
- 正文使用 `--fs-body`，说明/标签才可用 `--fs-sm`；内容多时先删冗词、减少阶段或拆页，不能缩小正文。
- 在网页 PPT 中使用时，保留宿主 deck 的概览、全屏、翻页、键盘和 URL 页码 runtime。这个模板只提供旅程页面主体，不替代 deck runtime。

## 选择呈现方式

| 情况 | 做法 |
|---|---|
| 需要展示一次完整经历和问题断点 | 使用本模板的六行旅程图 |
| 需要逐个讲解旅程中的几个问题 | 保留旅程图，叠加 report-ppt-skill 的证据聚光灯，不要重画成问题卡墙 |
| 两类用户在同一流程差异明显 | 每类用户各做一张旅程图，或只在同一张图中突出一个用户；不要把两套曲线硬塞同一格 |
| 只需要说明系统步骤、没有用户感受和研究证据 | 使用流程图，不触发本 skill |

## 验收

交付前按 `references/journey-pattern.md` 检查结构、内容映射和视觉。用浏览器以 16:9 桌面视口查看：阶段列不能错位、情绪曲线不能被压扁、文字不能溢出、机会点底部圆角必须闭合。
